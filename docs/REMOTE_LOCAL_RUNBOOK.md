# F09 — runtime locale di stato (RC16–RC21)

Pilota solo sullo stesso computer, Node 24. Nessun comando remoto, tunnel, pubblicazione, proxy gateway o collegamento iPhone. Non è un servizio Windows installato. Non usare in CI credenziali reali.

Preparare una directory di stato **locale**, assoluta e fuori dal repository, controllata esclusivamente dall'operatore autorizzato. Su POSIX: proprietario corrente, permessi 0700. Su Windows: verificare preventivamente con gli strumenti ACL del sistema che solo l'account autorizzato e gli amministratori di fiducia possano accedere (inclusi file ereditati); il runtime non verifica le ACL Windows. Niente filesystem di rete, cartelle sincronizzate, symlink o junction. Non usare directory in cui scrivono altri utenti/processi non fidati. Un solo host e agente per directory. Backup privato, non ripristinare un vecchio contatore con un grant ancora valido.

Da terminale locale interattivo, sostituire STATE con il percorso assoluto preparato:
- node --experimental-strip-types scripts/remote-local.ts register STATE pc
- node --experimental-strip-types scripts/remote-local.ts issue STATE pc node 60
- node --experimental-strip-types scripts/remote-local.ts issue STATE pc operator 60
- node --experimental-strip-types scripts/remote-local.ts serve STATE 8791

L'emissione visualizza intenzionalmente il token una sola volta nel terminale locale: disattivare registrazione/trascrizione e condivisione schermo; trasferire privatamente al vault già autorizzato, non salvare in cronologia, repo, log o file in chiaro. Se esposto, revocare immediatamente. Nessuna integrazione vault fornita. Il comando agent STATE 8791, con lo stesso prefisso node, accetta il solo token nodo attraverso stdin non interattivo (64 caratteri esadecimali, opzionale newline, EOF); collegare soltanto un vault locale approvato tramite pipe privata. Non usare argomenti o variabili d'ambiente per i segreti. Nessun esempio con token reale.

Revoca: node --experimental-strip-types scripts/remote-local.ts revoke STATE GRANT_ID da terminale amministrativo locale. Il processo agente si arresta al primo rifiuto; un errore transitorio non equivale a stato online. Ctrl+C arresta il runtime; il server attende la chiusura delle connessioni prima di chiudere SQLite. DB control.sqlite e agent.sqlite separati; non cancellare o ripristinare i contatori mentre le credenziali sono valide. Per rollback fermare i processi e revocare i grant prima di cambiare versione; conservare i DB privati.

MFA, TLS, ACL di rete, vault integrato, pairing, installazione servizio Windows, UI e prova cellulare rimangono obbligatori prima del controllo remoto. Nessuna esposizione di 8791 o 8787. Test RC16–RC18 non equivalgono a un collaudo Windows fisico. 

## Consultazione operatore (RC20–RC21)
Il comando `node --experimental-strip-types scripts/remote-local.ts status 8791` legge lo stato da loopback; riceve la credenziale **operator** da un vault locale autorizzato tramite stdin privato, con lo stesso formato del comando agent. Non richiede accesso al DB. In caso di successo restituisce soltanto JSON validato con node, online e lastSeenAt (timestamp Unix in ms o null). Un rifiuto, una revoca, un timeout o una risposta invalida terminano con codice 1, stderr generico e nessun JSON; non interpretare tali casi come offline. Non passare token sulla riga di comando o in env. Nessun comando remoto o accesso allo smartphone; il vault e il trasporto privato non sono ancora implementati.
Il test RC19 usa URL esplicito di node:url per evitare il conflitto con i tipi globali Expo. RC20–RC21 verificano subprocess locale, ruolo, revoca, porta gateway vietata e redazione; gli esiti devono essere osservati prima di dichiarare PASS.

## RC22–RC24 — archivio cifrato locale (candidato)
Usare una seconda directory privata VAULT, con le stesse verifiche POSIX/ACL Windows indicate sopra. Il vault SQLite usa AES-256-GCM con nonce casuale, autenticazione del ruolo e inserimento atomico senza sovrascrittura. Non è un keychain del sistema operativo: occorre una chiave casuale indipendente di 32 byte, custodita da un key source locale approvato; non conservare chiave e archivio insieme. Le stringhe JS possono permanere in memoria; la cifratura non protegge da un processo compromesso o amministratore locale.
Comandi (prefisso node --experimental-strip-types scripts/remote-local.ts): vault-import VAULT operator oppure node riceve via pipe privata due righe esadecimali minuscole di 64 caratteri, chiave e token già emesso, poi EOF. status-vault VAULT PORT e agent-vault STATE PORT VAULT ricevono solo la chiave via pipe privata. Nessun argomento/env per chiave o token, nessuna stampa del token. Per ruotare: revocare il grant dal controllo locale, emetterne uno nuovo e importare in nuova directory privata, senza riutilizzare un backup di grant. Non usare un terminale registrato o un file in chiaro come pipe source. Il comando non crea o rinnova grant. Il controllo di autorizzazione resta sul server, anche se il vault viene ripristinato. RC22–RC24 predisposti; CI non ancora osservata. OS keychain/DPAPI, provisioning Windows, MFA/TLS e collegamento iPhone restano aperti.

## RC25–RC27 — fonte chiave Windows DPAPI (candidato)
Windows PowerShell 5.1 di sistema, Node 24, profilo dell'account autorizzato caricato. Nessuna dipendenza o servizio a pagamento. La fonte usa ProtectedData CurrentUser (https://learn.microsoft.com/dotnet/api/system.security.cryptography.protecteddata?view=netframework-4.7.2). La chiave AES casuale da 32 byte è protetta dal profilo Windows, mai scritta in chiaro; il helper consegna i 64 caratteri esadecimali soltanto nella pipe anonima catturata da Node, non lanciarlo direttamente. Il vault rimane AES-GCM e la revoca resta lato controllo. Nessun fallback, bypass execution policy, installazione servizio o accesso di rete. Non usare amministratore elevato, transcript/debugger o checkout modificabile da altri. Le ACL e la proprietà di KEYDIR, VAULT, STATE e dei loro parent devono essere verificate prima di usare dati reali; usare directory separate, locali, fuori repo, non sincronizzate e senza junction/reparse point. Non confondere DPAPI CurrentUser con MFA o isolamento da altri processi dello stesso account.
- Prefisso node --experimental-strip-types scripts/remote-local.ts: vault-key-init KEYDIR (crea solo una volta, non sovrascrive).
- vault-import-os VAULT operator KEYDIR oppure node: riceve il solo token emesso via pipe privata, EOF, niente argomento/env. Non usare un file in chiaro come sorgente.
- status-os VAULT PORT KEYDIR; agent-os STATE PORT VAULT KEYDIR. Non richiedono chiave manuale. Rifiutano la porta gateway; nessun output segreto su CLI.
- Se profilo, file o chiave non sono disponibili, errore chiuso. Non sostituire una chiave persa: revocare i grant, conservare privatamente gli archivi, inizializzare nuove directory, emettere e importare nuovi grant. Non copiare il blob su un altro account pensando che sia portabile.
- RC25 verifica il rifiuto fuori Windows; RC26–RC27 richiedono Windows reale con PowerShell e profilo caricato. Eseguire node --experimental-strip-types --test tests/remote-windows-key.test.ts. Test predisposti, non eseguiti nel nuovo candidato. Prova fisica, ACL effettive, servizio Windows, TLS/MFA/pairing e review ancora aperti.


## RC28–RC30 — avvio unico foreground (candidato)
Dopo provisioning DPAPI e import del grant **node** già emesso, usare `node --experimental-strip-types scripts/remote-local.ts run-os STATE 8791 VAULT KEYDIR` da checkout fidato. STATE, VAULT e KEYDIR devono essere directory locali private distinte, ACL verificate; arrestare prima gli altri host/agenti. Il processo apre il proprio listener loopback, non usa un listener esistente e stampa ready solo al primo heartbeat accettato. Porta 8787 vietata. Ctrl+C arresta entrambi; diniego (anche grant scaduto/revocato) termina con codice 2, indisponibilità con 1; nessun restart automatico. L'operatore usa status-os con grant operator separato. Un riavvio conserva sequenze SQLite: non ripristinare vecchie copie con grant validi. Non avviare con account SYSTEM o elevato, non esporre listener, non usare tunnel. L'avvio automatico via scheduler Windows è un futuro collaudo separato: nessun task installato; il grant ha TTL massimo 24 ore e non si rinnova da solo. RC28–RC30 provano host HTTP/SQLite sintetici, non DPAPI su Windows reale o smartphone; CI nuova non ancora osservata. Rollback: fermare, revocare grant e conservare archivi privati come sopra.
