# F14 N3 — ingress GitHub Actions autenticato (candidato)

Il modulo riceve byte originali e firma X-Hub-Signature-256 da un futuro adapter autorizzato. Nessun listener o webhook è attivato. Solo workflow_run completed con esito success/failure/timed_out, scope locale owner, repository ID + full_name e workflow ID, segreto distinto per binding (minimo 32 byte da vault autorizzato, non nel repo). L'header delivery ID non è firmato, quindi non è usato per dedup. Run ID e attempt dal payload firmato identificano l'evento; l'inbox SQLite conserva dedup dopo riavvio. Finestra timestamp 24h, tolleranza futura 60s; clock attendibile obbligatorio. Non cancellare la dedup durante la validità dei payload. Una modifica conflittuale dello stesso run/attempt non viene pubblicata. Nessun titolo, URL arbitrario, actor, branch o raw payload persistito; solo riferimenti e riassunto fisso. Success non prova disponibilità artefatti.

Test N3a–d: firma e scope, percorso inbox/outbox/worker sintetico, replay/riapertura e opt-in, rerun, scadenza e input malformato. Il secret fixture non è una credenziale reale. Prima dell'attivazione: autenticazione dell'operatore, binding e rotazione vault, limite streaming e rate limit all'ingress, trasporto TLS approvato, collaudo GitHub reale autorizzato, CI e RV-01. Nessuna esposizione del gateway. Rollback disattivando ingress e preservando DB e stato consegna. F09/F13 indipendenti; nessun nuovo costo.
